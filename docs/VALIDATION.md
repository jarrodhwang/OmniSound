## Executed

- On 2026-10-01, the audio path was revised for source fidelity and crackle recovery: shared 128-tap/1024-phase interpolated sinc, double accumulation, exact integer-frame PCM sampling, smoothly filtered clock/phase/gain changes, short gap/idle/reconnect fades, and float headroom without premature +/-1 clipping. Zero-weight filter endpoints no longer require unavailable samples. RAW output negotiation has compatible normal-mode fallback. Valid presentation anchors permit startup before the drift fit fully converges.
- The current 20-case core suite passes, including 17/20 kHz fractional stereo reference error (110.191 dB signal-to-error; maximum error 4.59e-6), integer PCM identity, unused-tap starvation, packet-gap/partial-fade restart edges, float headroom, smooth gain/clock changes, and the quality analyser's known DC/phase/rate/distortion cases. Windows contracts, WinUI deployment/input/tray/theme/layout and installer wizard tests also pass. The 110 dB figure is a mathematical resampler check, not a device or acoustic SNR specification.
- On the installed current engine, a 60-second uncompressed 48 kHz stereo float32 test through the Realtek headphone default and the two selected DELL S2725DS mirrors completed while a native build ran concurrently. Six independent channel/frequency cases cover 997/1499, 9973/12011 and 18013/19001 Hz. Each mirror had 191 analysed 100 ms windows per band, zero dropout windows, zero active missing frames, zero underrun buffers, zero render starvation/resyncs and zero invalid samples. Median signal-to-residual was about 65–68 dB on the mirrors, with the maximum median loss against the simultaneous reference 1.7804 dB. Worst-window residuals remain separate in the raw result; this local relative-fidelity check is not standardized THD+N, an acoustic quality certificate, or proof for Bluetooth/other devices. Evidence: `build/validation/audio-quality-release-check-60s.json` and `audio-quality-acceptance.json`.
- A normal six-second source test and a RAW-requested diagnostic source test show a large source-processing difference: normal Realtek tone purity is roughly 19–25 dB signal-to-residual, versus roughly 66–69 dB with RAW active. The user's global Windows effects settings, source volume, saved groups and startup preference are not changed by the test. RAW can retain always-on endpoint/hardware processing. No microphone or audio recording file is used; offline signal windows exist only in bounded process memory.
- Both actual DELL endpoints passed a silent 120 ms deliberate diagnostic-render stall and recovery. Recovery detects empty queues even when hardware frame positions stop advancing, reseeds the QPC presentation anchor and handles counters that advanced beyond submitted frames. One stall was counted on each diagnostic stream; the rebased prediction error was about -0.0002 ms. This is adapter/timeline recovery evidence, not an acoustic synchronization measurement. Evidence: `audio-quality-render-recovery.json`.

## Release acceptance matrix

1. Obtain a Microsoft-signed driver package and Authenticode-signed application/installer binaries. `tools/Package.ps1 -Release` must pass. Confirm ordinary Secure Boot/HVCI remain enabled.
2. On a clean test machine, install, create two groups, rename one, reboot, delete the other. Verify stable Windows endpoint identity, label and selection. Remove the product and confirm no functioning OmniSound endpoint or service remains.
3. Route deterministic PCM into one virtual endpoint. Verify independent left/right channels, Windows master gain/mute and per-app volume exactly once; verify silence followed by audio. Ensure an app choosing a physical device directly is unaffected.
4. Use at least two independent physical outputs and an independent simultaneous measurement path. Measure repeated bursts before/after calibration at a documented position. Require the worst inter-device spread including uncertainty to remain within 1 ms for any combination claimed to meet that target.
5. Repeat with wired+wired, wired+Bluetooth, Bluetooth+Bluetooth. Record failures as unsupported timing combinations, never as a successful lock. Run >=60 minutes and record clock drift, discontinuities, acoustic drift, CPU and private bytes.
6. Unplug one member, power off a monitor, change an output format, open a Bluetooth microphone, suspend/resume, terminate the engine, restart AudioSrv/service. Remaining outputs should continue when possible; returning streams must fade in and measurement validity must be cleared.
7. Test keyboard navigation, 100/150/200% DPI, high contrast, duplicate endpoint names, missing microphone, clipping/low SNR, cancellation and configuration edits during calibration. No partial calibration may overwrite a newer configuration.
8. Run Driver Verifier and the relevant HLK audio/device tests on a disposable test host. Validate recovery, secure installation and cleanup before publishing.
